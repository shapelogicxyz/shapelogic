# The puzzles the comparison harness runs, relative to the original BurrTools
# checkout (BT_OLD_REPO, default ../burrtools_rotations).
#
# Columns: tier  flags  path-or-glob
#   tier  fast  every run (seconds in total)
#         full  before finishing a solver stage (minutes)
#         slow  benchmarks and final checks only (minutes each)
#   flags "-" none
#         "R" rotation take-apart (-R)
#         "A" assemble only: the grid has no take-apart (spheres, rhombic,
#             tetra-octa). The original burrTxt --json always takes apart and
#             aborts on these grids, so the harness reads its plain `-q`
#             summary instead; the new bt --json must report assemblies with
#             solutions 0 and no level.
#         "N" sliding: --nested-slides; "P" sliding: --partial-nested
#         "L" sliding: a full search would not end (or takes minutes): only
#             the fast and deep solvers run it
#         "O" sliding: several starts. A shorter path to a picture already
#             counted counts again, so on several threads the counts depend
#             on the order the starts come in (in the original too): the
#             baseline is one thread's (every sliding one is) and these are
#             compared with --threads 1 only
#   tier  sliding  the sliding puzzles (deferred part 1): run with
#         `--tier sliding` and `--solver fast|deep|full` (the default is the
#         full search, burrTxt's). "alpha:" paths are files of this repo:
#         the puzzles of the original's test/test_sliding.cpp made with its
#         own code (`oracle.py sliding-puzzles`).
#
#   tier  stacking  the stacking puzzles (deferred part 3): run with
#         `--tier stacking` and `--solver panex` for the Panex Solver (the
#         default is the Stacking Solver, burrTxt's). "alpha:" paths are the
#         puzzles of the original's test/test_stacking.cpp made with its own
#         code (`oracle.py stacking-puzzles`).
#         "Q" stacking: the Panex Solver does not take it (no Panex columns,
#             or more rods than it holds): not run with --solver panex
#         "L" stacking: its further problems run for hours: no `-o all` run
#         "I" stacking: its setup is not ready (setupError): the GUI's Solve
#             refused it, so no solved file is made or compared
#
# Never add the commercial sliding puzzle "One Way or Another".
